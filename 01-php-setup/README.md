## Что такое веб-сервер

Веб-сервер — это программа (или устройство), которая принимает HTTP-запросы, обрабатывает их и возвращает HTTP-ответы. Ключевая функция — отдавать контент по протоколу HTTP (или HTTPS).

Стоит различать два смысла термина:

- **Аппаратный веб-сервер** — физическая машина, на которой работает соответствующее ПО.
- **Программный веб-сервер** — само ПО: Apache, Nginx, IIS. В современной веб-разработке «веб-сервер» почти всегда означает именно программное обеспечение.

Веб-сервер может размещать один или несколько сайтов с помощью виртуальных хостов. Виртуальный хост — это механизм, позволяющий одному веб-серверу обслуживать несколько доменов на одной машине. Apache называет их `VirtualHost`, Nginx — Server Blocks.

### Как браузер общается с сервером

1. Браузер отправляет HTTP-запрос (метод, путь, заголовки).
2. Веб-сервер принимает запрос и определяет, какой файл или скрипт должен его обработать.
3. Если это PHP-файл, сервер передаёт его PHP-интерпретатору.
4. PHP выполняет код и возвращает HTML.
5. Веб-сервер отправляет HTTP-ответ обратно браузеру.

Если сервер не находит запрошенный файл, он возвращает код состояния **404**. Кодов состояния много, и они сгруппированы по категориям:

- **2xx** — успех (`200 OK`)
- **3xx** — перенаправление (`301 Moved Permanently`, `302 Found`)
- **4xx** — ошибка клиента (`403 Forbidden`, `404 Not Found`)
- **5xx** — ошибка сервера (`500 Internal Server Error`)

Два самых распространённых веб-сервера — **Apache** и **Nginx**.

## Как настроить локальную среду для PHP

Есть разные способы установить PHP, в том числе вручную. Для упрощения задачи используют универсальные решения:

- **XAMPP**
- **MAMP**
- **WAMP**

Они объединяют веб-сервер, PHP, базу данных и другие инструменты. Автор рекомендует начать с XAMPP, но отмечает его минусы:

- нельзя установить несколько версий PHP «из коробки»;
- сложно управлять несколькими проектами;
- не подходит для продакшена из-за проблем с безопасностью (MySQL-рут по умолчанию без пароля, некоторые модули уязвимы по умолчанию, конфигурация оптимизирована под удобство, а не под безопасность).

Главный стратегический вывод: не застревать на XAMPP. Для дальнейшего обучения (Docker, Nginx, PHP-FPM) XAMPP становится обузой. Во второй части курса автор переходит на Docker.

## Установка и запуск XAMPP

1. Скачайте XAMPP с официального сайта.
2. При установке выберите только нужные сервисы (в курсе используют только БД и PHP).
3. Запустите панель управления XAMPP.
4. Проверьте, не занят ли нужный порт другими службами — иначе возникнет ошибка. По умолчанию HTTP работает на порту `80`, HTTPS — на `443`. Если порт `80` занят (Skype, IIS, другая служба), Apache не запустится. Решение — сменить порт в `httpd.conf` на `8080`.
5. Перейдите в браузере по адресу `http://localhost` — если открылась страница приветствия XAMPP, сервер работает.

Исходный код проекта помещают в каталог **`htdocs`** — корень документа. При запросе к директории Apache ищет индексные файлы, заданные в конфигурации. По умолчанию это обычно `index.php`, `index.html`, `index.htm`. Если ни одного нет — либо выдаётся листинг директории (если разрешён), либо `403`/`404`.

## Наиболее распространённые веб-серверы

### Apache HTTP Server

Часто просто Apache.

- Бесплатный, с открытым исходным кодом.
- Поддерживает множество ОС: Windows, Linux, Unix, FreeBSD, macOS и др.
- Отличается гибкостью и модульностью — можно подключать тысячи модулей для разных задач.
- Имеет механизм `.htaccess` — файлы конфигурации на уровне директории, что удобно для виртуального (shared) хостинга. Важно: для работы `.htaccess` в `httpd.conf` должен быть разрешён `AllowOverride`. Без этого Apache игнорирует `.htaccess`.
- Использует процессную или потоковую модель обработки запросов (на каждое соединение создаёт отдельный процесс или поток), из-за чего может потреблять много оперативной памяти.
- Долгое время был самым популярным веб-сервером в мире.

### Nginx

Произносится «э́нджин-икс».

- Бесплатный, с открытым исходным кодом.
- Отличается высокой скоростью работы и низким потреблением ресурсов.
- Построен на асинхронной событийно-ориентированной архитектуре (event-driven), что позволяет эффективно обрабатывать большое число одновременных соединений (решает т. н. проблему C10k).
- Часто используется как обратный прокси (reverse proxy), балансировщик нагрузки или CDN-узел.
- Популярен для высоконагруженных сайтов и в гибридных схемах (например, Nginx отдаёт статику и проксирует запросы к Apache для обработки PHP).

### Microsoft IIS (Internet Information Services)

- Нативный веб-сервер для экосистемы Windows Server (работает только на Windows).
- Глубоко интегрирован с другими продуктами Microsoft: Active Directory, MS SQL Server, ASP.NET и т. д.
- Управляется через графический интерфейс, что упрощает настройку для пользователей Windows.
- Основной выбор для приложений на ASP.NET или .NET Core.

### Другие заметные решения

- **LiteSpeed** — быстрый, событийно-ориентированный.
- **Caddy** — простота настройки и автоматический HTTPS.
- **Lighttpd** и др.
